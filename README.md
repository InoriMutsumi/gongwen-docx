# gongwen-docx

给 AI 代理用的 Word 排版技能：产出 `.docx` 时默认套用中国党政机关公文版式（GB/T 9704-2012 的**版式部分**）。

只要它要写 Word 文档，就自动用这套字体、字号、行距、版心；用户说一句「不用公文格式」立刻退回普通排版。

## 为什么只做版式，不做红头

份号、密级、紧急程度、发文机关标志、发文字号、签发人、红色分隔线、版记、印章——这九样一律不生成。

原因很简单：这里要的是**读起来舒服、全篇一致**的文档，不是送审的红头文件。所以正文从标题直接起排，没有红头和分隔线。

保留了正式文书的骨架：标题 → 主送机关 → 正文 → 附件说明 → 发文机关署名 → 成文日期 → 附注 → 页码。

## 仓库内容

```
SKILL.md                 # 技能本体：参数表、结构规则、自检清单
scripts/gongwen_docx.py  # 参考实现，一条命令生成合规 .docx
tests/                   # 回归测试（unittest，不依赖真实字体）
requirements.txt         # 运行与测试依赖
```

## 安装

把 `SKILL.md` 和 `scripts/` 放进代理的技能目录（DSH 默认是 `~/.dsh/skills/gongwen-docx/`）：

```
~/.dsh/skills/gongwen-docx/SKILL.md
~/.dsh/skills/gongwen-docx/scripts/gongwen_docx.py
```

也可以不装技能，直接当脚本用：拷走 `scripts/gongwen_docx.py`，`pip install python-docx` 就能生成。

## 版式参数

| 项目 | 取值 |
| --- | --- |
| 纸张 | A4，页边距上 37 / 下 35 / 左 28 / 右 26 mm |
| 版心 | 156 × 225 mm，每页 22 行（行跨度 580 twips）；每行字数由版心宽和 3 号字宽自然排出，约 28 字，脚本不强制字符网格 |
| 正文 | 仿宋_GB2312 三号（16 pt），固定行距 29 磅，首行缩进 2 字 |
| 标题 | 方正小标宋简体二号（22 pt），居中，上方留 2 行 |
| 一级标题「一、」 | 黑体 三号 |
| 二级标题「（一）」 | 楷体_GB2312 三号 |
| 三级标题「1.」 | 仿宋_GB2312 三号 |
| 成文日期 | 阿拉伯数字标全，右空 4 字；署名以日期为准居中 |
| 页码 | 宋体 四号（14 pt），格式 `— 1 —`，单页居右空 1 字、双页居左空 1 字 |

## 用脚本生成

```bash
python scripts/gongwen_docx.py \
  --out 通知.docx \
  --title "关于××××工作的通知" \
  --to "各处室：" \
  --body 正文.txt \
  --sign "××××办公室" \
  --date "2025 年 10 月 25 日" \
  --attach "1. ××××表" \
  --note "（此件公开发布）"
```

`正文.txt` 用前缀标层级：

```
# 一级标题（黑体，「一、」自己写）
## 二级标题（楷体，「（一）」自己写）
### 三级标题（仿宋，「1.」自己写）
#### 四级标题（仿宋，「（1）」自己写）
\# 行首真要写井号的正文行（反斜杠被吃掉，井号保留）
普通行按正文段排
```

两条规矩：

- **空行分段**：连续的非空普通行合并成一个正文段，中文直接相连、英文数字之间补半角空格。从 PDF、网页粘来的硬换行不会把一段拆成好几段。整份文件一个空行都没有时退回「一行一段」，不会把整篇合并成一大段。
- **编号自己写**：`#`、`##`、`###` 只换字体，不自动加编号。

其他参数：

| 参数 | 作用 |
| --- | --- |
| `--check-fonts` | 只检查字体，不生成文件 |
| `--force`（别名 `--allow-missing-fonts`） | 字体缺失时仍然生成（只放行，不替换字体名） |
| `--hide-first-page-number` | 首页不编页码（默认首页也显示） |
| `--attach` | 附件说明，可重复；自带「附件：」前缀会被去掉 |
| `--note` | 附注，如「（此件公开发布）」 |

退出码：

| 退出码 | 含义 |
| --- | --- |
| `0` | 成功 |
| `1` | 参数、读取或写入错误（含空白标题、空正文、`--out` 不是 .docx、日期非法、`--to` 缺全角冒号、写文件失败） |
| `2` | 缺字体，未获放行 |
| `3` | 缺 python-docx |
| `4` | 文档已生成，但页码没写进去 |
| `5` | 字体检测不可用（非 Windows，或注册表和字体目录都读不到），未获放行 |

拦下时不生成任何文件，也不会留下 `.tmp` 半成品。

## 缺字体怎么办

规范的字体是**方正小标宋简体**、**仿宋_GB2312**、**楷体_GB2312**、**黑体**、**宋体**，都要自己装，仓库不带字体。

生成前先查：

```bash
python scripts/gongwen_docx.py --check-fonts
```

- 齐全 → 退出码 `0`，继续。
- 缺失 → 退出码 `2`，**不生成任何文件**，把缺的字体逐条列出来；加 `--force` 才继续。
- 检测不可用（非 Windows 系统，或注册表和字体目录一条都读不到）→ 退出码 `5`。这不是「字体齐全」，也不再假装查过：先把原因告诉用户，请他确认字体已装，再加 `--force`。

`--force` 只放行，**不会替换字体名**：文档里写的仍是「仿宋_GB2312」这些规范名，缺的那款由 Word / WPS 打开时用系统字体顶替，显示效果不可控。真要有把握，还是把字体装上——把「仿宋_GB2312」偷偷换成「仿宋」，字宽变了，每页 22 行就算错了。

## 关掉

用户说「不用公文格式 / 普通排版 / 随便排」，本次以及本轮后续文档立刻回到普通排版；再说「用公文格式」就恢复。

## 依赖

- Python 3.8+
- `python-docx`
- 上述五款中文字体（Windows 自带「黑体」「宋体」，其余需另装）

字体检测只支持 Windows（读注册表和系统字体目录）；其他平台返回 `5`，按「无法确认」处理。

跑测试：

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
```

## 测试与实测

- 回归测试：`tests/test_gongwen_docx.py`，33 个用例，覆盖分段规则、四级标题、`\#` 转义、日期与附件前缀校验、各类退出码、页边距/字体/字号/行距/缩进/页码域、原子写入不留 `.tmp`。测试对字体查找打桩，**不需要装那五款字体**，Linux CI 也能跑。
- 真机核对：脚本在 Windows + Word 上真跑过，生成的文档用 Word 打开后逐项核对了页边距、字体、字号、行距、缩进、页码位置，并渲染成图看过版面；附注、附件说明、署名居中等边界情况，以及缺字体、页码失败、参数非法这些失败路径也都单独测过。

`SKILL.md` 里的每个数字都能在脚本里找到对应实现，两边不一致算 bug。
